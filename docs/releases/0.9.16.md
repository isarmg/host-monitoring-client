# Host Monitoring Client 0.9.16

This release repairs Setup after Server state loss. Setup now distinguishes a local binding from a credential that the configured Server has remotely verified, prompts before reusing a verified binding, and identifies an authorization rejected by a rebuilt Server as stale instead of reporting a false pairing success.

`host-monitor pair recover --interactive` issues a new credential while preserving the durable Host UUID and all queued reports. The Server refuses recovery if that UUID already exists. Administrators who intentionally choose a new identity can first use `host-monitor queue archive --reason server-state-lost`; this atomically retires the old spool beneath `retired-bindings/<host-id>/` with a manifest instead of deleting or relabeling reports.

Interactive connection verification prints progress every five seconds and is bounded by the requested outer timeout even if a platform service-status call blocks. Delivery runtime state records the last attempt, result, HTTP status, and stable error code. A stable protocol-mismatch envelope is distinct from an invalid report and enters authorization recovery; proxy-generated or malformed responses remain retryable and cannot invalidate credentials.

The existing 0.9.4 persisted state format remains unchanged. A requested connection check that receives no real HTTP 202 acknowledgement is an error, and an interruption at that stage explicitly leaves the completed pairing committed.
