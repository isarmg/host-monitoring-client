# Host Monitoring Client 0.9.13

Setup now distinguishes an active and authorized binding from one marked `reauth_required`. Reauthorization performs the existing guarded replacement flow instead of repeatedly reusing a rejected credential. Before pairing or repair, setup stops a running service so the service-lifetime maintenance lock cannot block recovery.

Configuration, pairing, and a successfully started service now complete setup even when the first Server acknowledgement cannot be observed before the timeout. The machine-readable result records the connection step as a warning with `connection_unconfirmed`; `status --check` remains the strict health gate.

Installers no longer start interactive configuration from MSI or package post-install hooks. They install the binary, protected state and stopped service; the administrator then runs `host-monitor setup` in a real terminal. This removes UAC/TTY/package-manager coupling from first-run pairing.

The Client consumes Foundation Client 0.8.0 for stricter outbound network policy, explicit TLS trust, bounded recovery polling, Windows-safe entry names and pinned HTTP connection reuse. Native packages remain unsigned prerelease artifacts.
